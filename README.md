# 🎮 Club Bot — Telegram-бот для компьютерного клуба

**ДЕМО-ШАБЛОН для показа владельцу клуба.** Все данные (название «КИБЕР-ДЕМО»,
адрес, телефон, клиенты, брони, отзывы) — **ВЫМЫШЛЕННЫЕ**. Это универсальное
решение: под конкретный клуб меняются только настройки в `config.py` и тексты
в `texts.py` — код трогать не нужно.

Клиентам в демо-режиме каждый ответ бота начинается с пометки:
`🧪 ДЕМО-РЕЖИМ. Это пример бота для вашего клуба.`

---

## Что владелец клуба увидит за 3 минуты

1. **Клиент бронирует за 30 секунд** — кнопками по шагам или одним сообщением
   своими словами («завтра вечером часа на 3, нас двое») — текст разбирает
   **GigaChat**, неясное время бот уточняет кнопками.
2. **Админ получает карточку заявки** и подтверждает её одним нажатием
   `[✅ Подтвердить] [❌ Отклонить] [💬 Написать]`, клиент мгновенно получает ответ.
3. **Напоминание за 2 часа** до брони: `[✅ Приду] [❌ Не смогу]` — при отказе
   место освобождается, админ видит отмену.
4. **Запрос отзыва** через час после сеанса: оценка 4–5 → благодарность и ссылка
   на 2ГИС, оценка 1–3 → жалоба уходит владельцу.
5. **Статистика и управление через inline-панель**: после `/start` администратор
   получает разделы «Сегодня», «Статистика», «Клиенты», «Рассылка», «Настройки»
   и «Помощь». Команды сохранены как запасной способ навигации.

## Стек

- Python 3.10+, **aiogram 3.x** (Telegram Bot API)
- **SQLite** через `aiosqlite` (ничего не надо поднимать)
- **APScheduler 3.x** (напоминания и запросы отзывов)
- **GigaChat** (Сбер) — единственный AI-провайдер, официальный SDK `gigachat`

## Быстрый старт

```bash
git clone <url этого репозитория>
cd Club-bot

python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Дальше — 3 шага. Настройки можно задавать **двумя способами**: править
`config.py` **или** заполнить `.env` (он имеет приоритет, шаблон —
`.env.example`):

```bash
cp .env.example .env   # и впишите свои значения
```

1. **Токен бота.** В Telegram откройте **@BotFather** → `/newbot` → получите
   токен → вставьте в `BOT_TOKEN`.
2. **ID админа и владельца.** Свой числовой ID можно узнать у **@userinfobot**
   → впишите в `ADMIN_ID` и `OWNER_ID` (можно один и тот же).
3. **Важно:** админ должен первым написать боту `/start`. Telegram запрещает
   ботам писать первыми — иначе карточки заявок админу не дойдут.

```bash
python main.py
```

Бонус: **ключ GigaChat не обязателен** — без него бот полностью работает на
кнопках (AI отключится сам, ошибок не будет). База предзаполнена демо-данными:
владелец сразу увидит «живые» разделы «Сегодня» и «Статистика» в админ-панели.

## Как получить ключ GigaChat (Сбер)

1. Зайдите на **developers.sber.ru** → Studio → авторизуйтесь.
2. Создайте проект **«GigaChat API»**.
3. В авторизационных данных проекта скопируйте **Ключ авторизации**
   (Authorization key) — длинную строку вида `MDE5...`. Ключ Studio формирует
   сама: **копируете и вставляете как есть**, ничего кодировать не нужно.
4. Вставьте ключ в `config.py`:
   ```python
   AI_API_KEY = "MDE5..."            # Ключ авторизации из Сбер Studio
   AI_SCOPE   = "GIGACHAT_API_PERS"  # для физлиц (бесплатный freemium)
   USE_AI     = True
   ```

В коде всё работает в точности как в примере из документации SDK:

```python
from gigachat import GigaChat
from gigachat.models import Chat, Messages, MessagesRole

giga = GigaChat(credentials="Ключ авторизации", verify_ssl_certs=False)
giga.chat(Chat(messages=[Messages(role=MessagesRole.USER, content="Привет!")]))
```

Нюансы:
- **Токен доступа живёт 30 минут** — SDK обновляет его автоматически.
- Нужны **сертификаты Минцифры** — оставьте `AI_VERIFY_SSL = False`, SDK
  подставит их сам.
- Документация: https://developers.sber.ru/docs/ru/gigachat

### Модель и лимиты

Бот использует **одну дешёвую модель `GigaChat-2` (Lite) для всех задач** —
и для разбора заявок текстом, и для ответов на вопросы FAQ. Меняется в
`config.py` → `AI_MODEL` (при желании можно поставить более качественные
`GigaChat-2-Pro` или `GigaChat-2-Max`).

- **Freemium (бесплатно, 12 месяцев):** 250 млн токенов Lite — для одного клуба
  с огромным запасом (всего в пуле 365 млн токенов: +40 млн Pro, +25 млн Max,
  +50 млн Ultra). Ограничение: один поток запросов — бот запрашивает
  последовательно, это учтено в коде.
- **Если freemium не хватит:** Lite 20 млн токенов — 1 300 ₽/мес,
  Pro 3 млн — 1 500 ₽/мес, Max 3 млн — 1 950 ₽/мес.

## Как заменить демо-данные на реальные

Всё меняется в начале **`config.py`** (комментарии есть у каждой строки):

| Переменная | За что отвечает |
|---|---|
| `BOT_TOKEN` | токен бота от @BotFather |
| `ADMIN_ID` / `OWNER_ID` | кому приходят заявки / жалобы 1–3⭐, кому доступны админ-команды |
| `USE_AI`, `AI_API_KEY`, `AI_MODEL`, ... | включение AI, ключ авторизации GigaChat и модель |
| `DEMO_MODE` | пометка «🧪 ДЕМО-РЕЖИМ» в ответах клиентам (поставьте `False` в проде) |
| `SEED_DEMO_DATA` | предзаполнение базы демо-клиентами (в проде — `False`) |
| `CLUB_NAME` / `CLUB_ADDRESS` / `CLUB_PHONE` / `CLUB_HOURS` | карточка клуба |
| `CLUB_MAPS_URL` / `CLUB_VK_URL` / `CLUB_SITE_URL` | кнопки-ссылки. **Пустая строка = кнопки нет** |
| `CLUB_PCS_TOTAL` | всего ПК — для оценки загрузки в `/week` |
| `TARIFFS` | цены в разделе «💰 Цены» и в базе знаний AI |
| `FAQ_BASE` | частые вопросы/ответы; GigaChat отвечает **строго** по ним |
| `TIME_SLOTS`, `DURATIONS`, `PCS_VARIANTS` | сетка бронирования |
| `TIMEZONE` | часовой пояс клуба (влияет на «сегодня» и напоминания) |

Все **формулировки** сообщений — в `texts.py`. После смены демо-данных удалите
старый файл базы `club_bot.db` (создастся заново) и выключите `SEED_DEMO_DATA`.

### Как отключить AI

Любой из вариантов:
- `USE_AI = False` (в `config.py` или `.env`), или
- просто оставить `AI_API_KEY = ""` — AI выключится автоматически.

Бот продолжит работать на кнопках **без единой ошибки**. Если в работе GigaChat
вернёт ошибку (невалидный ключ, кончился лимит, сеть) — бот залогирует причину
в `bot.log`, вежливо ответит клиенту и предложит кнопки. Технические ошибки
пользователю не показываются никогда.

## Переменные окружения (.env)

Любую настройку из `config.py` можно переопределить через переменные
окружения или файл **`.env`** в корне проекта (распознаётся через
`python-dotenv`; без пакета бот просто берёт значения из `config.py`).

**Приоритет:** переменные окружения (Railway, systemd, Docker) → файл `.env` →
значения по умолчанию в `config.py`.

**Обязательный минимум** в .env — три переменные:

```dotenv
BOT_TOKEN=123456789:AAEваш_токен_от_BotFather
ADMIN_ID=ваш_числовой_id
OWNER_ID=ваш_числовой_id
```

Плюс `AI_API_KEY=` — если нужен AI (без него бот работает на кнопках).

Полный список поддерживаемых переменных:

| Переменная | По умолчанию (демо) | Назначение |
|---|---|---|
| `BOT_TOKEN` | `СЮДА_ТОКЕН` | токен от @BotFather |
| `ADMIN_ID` / `OWNER_ID` | `123456789` | кому заявки/жалобы, доступ к админ-командам |
| `USE_AI` | `True` | `False` = бот только на кнопках |
| `AI_API_KEY` | *(пусто)* | Ключ авторизации из Сбер Studio; пусто = AI выключен |
| `AI_SCOPE` | `GIGACHAT_API_PERS` | scope (для физлиц — `..._PERS`) |
| `AI_MODEL` | `GigaChat-2` | одна дешёвая модель для парсинга и FAQ |
| `AI_VERIFY_SSL` | `False` | False → SDK сам ставит сертификаты Минцифры |
| `AI_TIMEOUT` | `30` | таймаут запроса к GigaChat, сек |
| `DEMO_MODE` | `True` | пометка «🧪 ДЕМО-РЕЖИМ» в ответах клиентам |
| `SEED_DEMO_DATA` | `True` | предзаполнение базы демо-данными |
| `CLUB_NAME` / `CLUB_ADDRESS` / `CLUB_PHONE` / `CLUB_HOURS` | демо-значения | карточка клуба |
| `CLUB_MAPS_URL` / `CLUB_VK_URL` / `CLUB_SITE_URL` | `https://2gis.ru/demo` / пусто / пусто | кнопки-ссылки; **пусто = кнопки нет** |
| `CLUB_PCS_TOTAL` | `10` | всего ПК (для загрузки в `/week`) |
| `REMIND_BEFORE_HOURS` | `2` | напоминание за N часов до брони |
| `REVIEW_AFTER_HOURS` | `1` | запрос отзыва через N часов после конца |
| `TIMEZONE` | `Europe/Moscow` | часовой пояс клуба |
| `DB_PATH` | `club_bot.db` | файл SQLite |
| `LOG_FILE` | `bot.log` | файл логов |

Нюансы:
- Булевы значения: `True/False` (также понимаются `1/yes/on`).
- Структурированные данные — **тарифы (`TARIFFS`) и база знаний (`FAQ_BASE`)** —
  в .env не выносятся, правятся в `config.py`.
- `.env` **не коммитится** (есть в `.gitignore`): там секреты. В репозитории
  лежит только шаблон `.env.example`.
- Рабочий пример с демо-значениями — в файле `.env` рядом с этим README.

## Админ-панель

Пользователь, чей Telegram ID указан в `ADMIN_ID` или `OWNER_ID`, после
`/start` видит отдельную inline-панель. Клиентское меню для остальных
пользователей не меняется.

Основные разделы:

- **📅 Сегодня** — брони кнопками, карточка каждой брони, подтверждение,
  отмена, неявка, изменение даты/времени/длительности/числа ПК и сообщение
  клиенту;
- **📊 Статистика** — показатели за выбранный месяц, загрузка по дням недели и
  CSV-экспорт клиентов;
- **👥 Клиенты** — поиск по имени, телефону или username, сегменты постоянных,
  новых и неактивных клиентов, карточка, история и блокировка;
- **📢 Рассылка** — выбор аудитории, текст или фото с подписью, предпросмотр,
  прогресс и возможность остановить отправку;
- **⚙️ Настройки** — тарифы, FAQ, состояние AI, пауза клуба, список
  администраторов и экспорт базы;
- **❓ Помощь** — краткая справка по возможностям панели.

Списки броней, клиентов и FAQ разбиваются на страницы. Ввод при поиске и
редактировании выполняется пошагово через FSM. Все административные действия
проверяют права, а существенные изменения записываются в `bot.log`.

### Команды как запасной способ

Основной путь — inline-кнопки. Команды оставлены для привыкших пользователей:

| Команда | Что делает |
|---|---|
| `/start` | открыть админ-панель |
| `/help` | открыть справку |
| `/today` | перейти к броням на сегодня |
| `/week` | показать загрузку на неделю |
| `/stats` | перейти к статистике |
| `/find` | начать поиск клиента |
| `/broadcast` | открыть мастер рассылки |
| `/cancel` | сбросить текущий FSM-сценарий и вернуться в панель |

Доступ к панели и этим административным сценариям — только по `ADMIN_ID` и
`OWNER_ID`.

## Сценарий демонстрации владельцу (3 минуты)

1. Клиент (можно с того же телефона): `/start` → **🎮 Забронировать** →
   кнопками: Завтра → 19:00 → 2 ч → 2 ПК → имя → «⏭ Пропустить» телефон →
   ✅ Отправить заявку.
2. У админа приходит карточка — жмём **✅ Подтвердить**. Клиенту летит
   «✅ Бронь подтверждена».
3. Админ отправляет `/start` → **📅 Сегодня** — бронь появилась в списке;
   **📊 Статистика** — заявка учтена в показателях.
4. **⭐ Оставить отзыв** → 5⭐ → бот просит отзыв на 2ГИС (кнопка-ссылка).
   Ещё раз: 2⭐ + комментарий → жалоба пришла владельцу (`OWNER_ID`).
5. Если подключён ключ GigaChat: **🎮 Забронировать → 🤖 Написать текстом** →
   «завтра вечером часа на 2, нас трое» — бот сам распознал дату/длительность/ПК
   и уточнил конкретное время кнопками «вечера». В **❓ FAQ** напишите
   свободный вопрос — AI ответит из базы знаний.

## База данных (SQLite, `club_bot.db`)

| Таблица | Поля |
|---|---|
| `clients`  | `user_id, username, name, phone, visits, last_visit, created_at, blocked` |
| `bookings` | `id, user_id, date, time, duration, pcs, status, created_at` |
| `reviews`  | `id, user_id, rating, text, created_at` |
| `admin_settings` | внутренние переключатели панели (`AI`, пауза клуба) |
| `admin_tariffs` | тарифы, редактируемые из админ-панели |
| `admin_faq` | вопросы и ответы, редактируемые из админ-панели |

При запуске выполняется безопасная миграция старой базы: отсутствующее поле
`clients.blocked` добавляется без удаления существующих данных.

Статусы броней: `new` (ожидает) → `confirmed` / `rejected`, далее `cancelled`
(клиент отменил по напоминанию) / `noshow` (неявка).

## Логирование

Всё пишется в `bot.log` и дублируется в консоль:

```bash
tail -f bot.log
```

В лог идут: заявки, действия админа, работа планировщика, ошибки AI
(авторизация, лимиты, сеть) и недоставленные сообщения.

## Деплой

### VPS (systemd)

```bash
sudo apt update && sudo apt install -y python3-venv git
git clone <url> /opt/club-bot && cd /opt/club-bot
python3 -m venv venv && ./venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env   # токен, ID, ключ GigaChat (или правьте config.py)
```

`/etc/systemd/system/club-bot.service`:

```ini
[Unit]
Description=Telegram-бот компьютерного клуба
After=network.target

[Service]
WorkingDirectory=/opt/club-bot
# не обязательно: бот сам подхватит .env из рабочей папки
EnvironmentFile=/opt/club-bot/.env
ExecStart=/opt/club-bot/venv/bin/python main.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now club-bot
journalctl -u club-bot -f   # логи (и tail -f /opt/club-bot/bot.log)
```

### Railway

1. Запушьте репозиторий на GitHub (секреты в репозиторий не кладём — `.env`
   в `.gitignore`!).
2. **railway.app** → New Project → **Deploy from GitHub repo**.
3. Railway сам определит Python и установит `requirements.txt`;
   Start Command: `python main.py`.
4. **Settings → Variables** задайте переменные как в `.env.example`:
   минимум `BOT_TOKEN`, `ADMIN_ID`, `OWNER_ID` (и `AI_API_KEY` для AI).
   Они имеют приоритет над `config.py`, файлы править не нужно.
5. ⚠️ Файловая система на Railway **эфемерна** — `club_bot.db` и `bot.log`
   исчезнут при передеплое. Для постоянной базы подключите **Volume**
   (Settings → Volumes, точка монтирования `/data`) и добавьте переменную
   `DB_PATH=/data/club_bot.db`.

## Частые вопросы по запуску

- **Админу не приходят заявки.** Админ должен хотя бы раз нажать `/start` в боте;
  проверьте, что `ADMIN_ID` — числовой ID (узнать: @userinfobot).
- **AI не отвечает.** Проверьте, что в `AI_API_KEY` вставлен именно
  **«Ключ авторизации»** из Сбер Studio (целиком, без пробелов по краям),
  что `AI_SCOPE` соответствует вашему аккаунту, и посмотрите `bot.log`.
  Бот при этом продолжает работать на кнопках.
- **Кнопки 2ГИС/ВК/сайт не показываются.** Так задумано: пустая ссылка в
  `config.py` = кнопки нет. Заполните URL — кнопка появится.
- **«Сегодня» в боте не совпадает с реальным днём.** Поправьте `TIMEZONE`.
